# Using the package with AI agents

The package ships an agent skill: instructions for a coding agent (Claude Code and other agents that read Agent
Skills) on how to set up a resonance study, run it and read its verdicts. Install it into your project:

```bash
resonances skill install            # ./.claude/skills/resonances
resonances skill install --user     # ~/.claude/skills/resonances, for every project
resonances skill install --force    # replace an installed copy, e.g. after upgrading the package
```

`--path DIR` installs into another project folder. An existing copy is never replaced without `--force`. The agent
loads the skill in its next session; ask it, for example, "check 463 in 4J-2S-1 over 100 kyr and tell me whether it
is resonant", or "why is this row uncertain with short_period_aliased?".

## What the skill contains

- `SKILL.md`: the workflow and the judgement: which entry point to use (`check`, `find`, `Simulation`), how to plan
  the span, the output step and the integrator ([dry-run](dry-run.md)), clones, batch runs and restore, what each
  verdict field claims and does not claim, the usual traps, and a checklist before a status is reported to a person.
- `references/`: a copy of the pages of this documentation, generated from `docs/` (the installed package has no
  `docs/`). The formulas, columns and settings are therefore never written twice.

## For developers

The references are generated by `docs/tools/build_skill.py` (`make skill`); the list of copied pages is `PAGES` in
that script. Snippet includes are replaced by the code of `docs/examples/`, and links to pages that are not copied or
to images point to the published site. A fast test (`tests/resonances/skills/test_skill.py`) fails when the
references are out of date with `docs/`, so after editing a page run `make skill`. When a change alters the interface,
the statuses, reasons or caps, the settings or the output layout, update `resonances/skills/resonances/SKILL.md` too.
